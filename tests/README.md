# 봇 엔진 측정 도구

`index.html`의 게임 코드 안쪽에 `bench-harness.js`를 끼운 임시 페이지를 만들어(`load.js`) Playwright로 돌린다.
게임 파일 자체에는 영향이 없다. 실행 전 `NODE_PATH=$(npm root -g)` 필요.

| 스크립트 | 하는 일 |
|---|---|
| `make-puzzles.js <시드> <판 수> <출력>` | 자가 대국에서 공격(필승 수 찾기)/수비(상대 필승 막기) 문제를 뽑아 정답 목록까지 계산 |
| `run-puzzles.js [ms] [레벨들]` | `puzzles.json` 채점 + 평균 탐색 깊이·초당 노드 수 |
| `vct-check.js [수비 레벨] [ms]` | v2가 필승이라고 판단한 국면을 실제로 끝까지 이기는지 확인 |
| `tune.js '<E2P 일부>' <시드> <쌍 수> [ms]` | 평가 가중치 후보 vs 기본값 대국 (흑백 교대) |
| `match.js <레벨A> <레벨B> <시드> <쌍 수> [ms]` | 레벨끼리 대국 |
| `card-match.js <A> <B> <판 수> [ms] [무작위 수] [A 설정] [B 설정]` | 카드 포함 실제 게임 흐름 그대로 봇끼리 대국 (51 = 50에서 카드 개선 끔, 60/61 = 기능별 실험) |
| `make-book.js` / `merge-book.js` | 초반 국면을 깊게 계산해 `E2_BOOK`(정석)에 합침 |

## 결과 (슈퍼 울트라 짱짱맨 v2 도입 시점)

- 퍼즐 146문제(공격 55, 수비 91), 2초: Ultimate 139 → v2 141 / 초당 노드 10,330 → 33,961 (약 3.3배), 평균 깊이 6.0 → 7.2
- VCT 건전성: 필승 국면 55개 모두 Ultimate(3초) 상대로 실제 승리까지 연결 (55/55)
- 가중치 튜닝: 후보 8개 × 20판 → 상위 2개 × 60판 재검증 결과 모두 50% 안팎 → 기본값 유지
- 정석: 봇 백 4·6번째 수, 봇 흑 5번째 수 708국면 (국면당 10~15초 계산, 8대칭 조회 검증 통과)
- 대국: v2(50) vs Ultimate(20), 한 수 1초, 무작위 3수 시작 20쌍(흑백 교대) → **25승 15패 (62.5%)**
- 실제 화면 회귀: 짱짱맨 봇전 한 판 끝까지 진행(카드 사용 포함), 오류 없음
- 맞교환 위험 계산(`tradeRisk`): 상대에게 맞교환을 쥐여 준 퍼즐 146국면에서 "그 한 장에 지는 수"를 두는 경우 83 → 77,
  그중 다른 수로 피할 수 있었던 경우 11 → 5 (나머지는 어떤 수로도 못 피하거나, 피하면 상대 VCT가 생기는 국면). 퍼즐 점수 141/146 유지

## 카드 개선 (연속 착수 계획 · 카드 계획 v2 · 맞교환 공격 · 연속 착수 대비 · 카드 뽑기)

카드 포함 실제 대국, 한 수 1.5초, 흑백 교대, 기능을 하나씩 켜서 모두 끈 버전과 비교 (각 48판):

| 실험 | 결과 |
|---|---|
| 연속 착수 3수 계획 (처음 버전: 항상 계획을 따름) | 23 : 25 → 효과 없음 |
| 카드 계획 v2 (처음 버전: 연속 착수도 아껴 둠) | 23 : 25 → 효과 없음 |
| 맞교환 공격 + 상대 연속 착수 대비 + 카드 뽑기 | **30 : 18** |
| 위 셋 + 고친 연속 착수 계획(확실히 끝날 때만) + 고친 카드 계획(연속 착수는 바로 사용) vs 위 셋 | **30 : 18** |
| 최종 (전부 켬) vs 전부 끔 | **29 : 19 (60.4%)** |
| 폭파(풍차 돌 포함) · 공격용 풍차 · 함정+4 콤보 · 봉쇄 아끼기 (`cardPlan3`) 켬 vs 끔 (나머지 전부 켬) | **31 : 17 (64.6%)** |

- 버그 수정: 풍차 돌을 폭파해도 풍차 기록이 남아, 그 자리에 나중에 둔 돌이 풍차가 되던 문제 (`bombMillFix` 시나리오로 확인)
